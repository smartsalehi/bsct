# ارزیابی BSC برنامه حمل‌ونقل عمومی شهر

سامانه‌ای تک‌صفحه‌ای و سبک برای ارزیابی برنامه حمل‌ونقل عمومی شهری (اتوبوس، تاکسی، قطار شهری)
بر مبنای **مدل کارت امتیازی متوازن (Balanced Scorecard)**.

بدون فریم‌ورک، بدون وابستگی خارجی و بدون مرحله ساخت — فقط HTML، CSS و JavaScript خالص.

## چارچوب ارزیابی

| منظر | تمرکز | شاخص‌ها | جهت مطلوب |
| --- | --- | --- | --- |
| 💠 **مالی** | پایداری مالی و بهره‌وری منابع | پوشش هزینه عملیاتی؛ یارانه هر سفر؛ هزینه هر مسافر-کیلومتر | ↑ ↓ ↓ |
| 🧑‍🤝‍🧑 **مشتری** | رضایت و جذب مسافر | رضایت مسافران؛ سهم از سفر؛ شکایات | ↑ ↑ ↓ |
| ⚙️ **فرآیندهای داخلی** | نظم سرویس، سرعت، دسترسی | دقت زمان‌بندی؛ سرعت تجاری؛ دسترس‌پذیری ایستگاه | ↑ ↑ ↑ |
| 🎓 **یادگیری و رشد** | نیروی انسانی و ناوگان | ساعت آموزش؛ عمر ناوگان؛ سهم سوخت پاک | ↑ ↓ ↑ |

هر شاخص برای هر سه شیوه مقدار جداگانه دارد: **۱۲ شاخص × ۳ شیوه = ۳۶ داده**.

### فرمول امتیازدهی

هر شاخص بر پایه هدف خود به عددی بین ۰ تا ۱۰۰ نرمال می‌شود:

```text
مطلوب مثبت (هرچه بیشتر بهتر):  Score = min(100, Value ÷ Target × 100)
مطلوب منفی (هرچه کمتر بهتر):   Score = min(100, Target ÷ Value × 100)
```

سپس امتیاز منظر و امتیاز کل محاسبه می‌شود:

```text
Perspective = Σ Scoreᵢ ÷ n
Overall     = Σ (Wₚ × Perspectiveₚ) ÷ Σ Wₚ
```

| سطح امتیاز | تفسیر |
| --- | --- |
| ۸۵ – ۱۰۰ | عملکرد ممتاز — الگوی قابل تعمیم |
| ۷۰ – ۸۵ | عملکرد خوب — نیازمند بهبود هدفمند |
| ۵۵ – ۷۰ | عملکرد متوسط — اولویت‌بندی اقدامات |
| زیر ۵۵ | عملکرد ضعیف — مداخله فوری |

## انتشار در GitHub Pages

> 📤 **اولین بار است آپلود می‌کنید؟** راهنمای گام‌به‌گام (نصب Git، ساخت توکن، احراز هویت و رفع خطاها) را در
> [UPLOAD-GUIDE.md](UPLOAD-GUIDE.md) ببینید.

### الف) انتشار خودکار (پیشنهادی)

مخزن شامل workflow آماده در `.github/workflows/pages.yml` است.

```bash
git init
git add .
git commit -m "feat: BSC public transport evaluation site"
git branch -M main
git remote add origin https://github.com/<USERNAME>/<REPO>.git
git push -u origin main
```

سپس در مخزن GitHub:

1. به **Settings → Pages** بروید.
2. در بخش **Source** گزینه **GitHub Actions** را انتخاب کنید.
3. پس از پایان اجرای workflow، سایت در آدرس زیر در دسترس است:

```text
https://<USERNAME>.github.io/<REPO>/
```

هر `push` روی شاخه `main` به‌طور خودکار سایت را به‌روزرسانی می‌کند.

### ب) انتشار سریع بدون Actions

1. به **Settings → Pages** بروید.
2. در **Source** گزینه **Deploy from a branch** را انتخاب کنید.
3. شاخه `main` و پوشه `/ (root)` را انتخاب و ذخیره کنید.

> مسیرهای فایل‌ها **نسبی** هستند (`css/style.css`، `js/main.js`)، بنابراین سایت در زیرمسیر
> `/<REPO>/` هم بدون تغییر درست بارگذاری می‌شود.

### ج) انتشار روی دامنه اختصاصی

یک فایل `CNAME` در ریشه مخزن بسازید و دامنه را در آن بنویسید:

```text
example.com
```

سپس در DNS دامنه، رکوردهای `A`/`CNAME` را مطابق راهنمای GitHub تنظیم کنید.

## شخصی‌سازی

| بخش | محل تغییر |
| --- | --- |
| شاخص‌ها، اهداف و مقادیر | `INDICATORS` در `js/main.js` |
| نام و آیکون شیوه‌ها | `MODES` در `js/main.js` |
| عنوان و توضیح منظرها | `PERSPECTIVES` در `js/main.js` |
| وزن پیش‌فرض منظرها | `DEFAULT_WEIGHTS` در `js/main.js` |
| رنگ شیوه‌ها و تم | `--bus`، `--taxi`، `--metro` و `:root` در `css/style.css` |
| متن‌ها، بخش‌ها و نقشه استراتژی | `index.html` |

### افزودن شاخص جدید

```js
{
  id: "newKpi",              // شناسه یکتا
  perspective: "customer",   // financial | customer | internal | learning
  name: "عنوان شاخص",
  unit: "٪",
  target: 80,
  direction: "up",           // up = هرچه بیشتر بهتر، down = هرچه کمتر بهتر
  values: { bus: 55, taxi: 62, metro: 71 },
}
```

پس از افزودن، جدول، امتیاز منظر، امتیاز کل و نمودار راداری خودکار به‌روز می‌شوند.
